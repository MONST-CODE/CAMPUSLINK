# Build and local release

`build.bat package` builds/takes tests in Release, builds a fresh ZIP, verifies the manifest and hashes, extracts it under a directory with spaces and runs SDL + ImGui smoke tests from it. `build.bat release-all` also rebuilds and tests Debug before generating `dist/releases/v<VERSION>/`. It refuses to overwrite a versioned local release; move it aside before repeating the command. The local command does not publish to GitHub.

Portable output: `dist/packages/CAMPUSLINK-<VERSION>-windows-x64-portable.zip` plus `.sha256`. The local release contains the ZIP, manifest, build information, dependency inventory, notes, checksums and verification report. `manifest.json` describes payload entries (not itself); `SHA256SUMS.txt` verifies the whole ZIP and standalone manifest. Run `powershell -NoProfile -File scripts\verify-release.ps1 -Archive <zip>` against `dist/packages` or also pass `-ReleaseFolder <folder>` for a versioned local release. SHA-256 checks integrity, not authorship. Timestamps are included by design; bit-identical ZIPs are not claimed.

`RUNTIME_IMPORTS.txt` is generated by `dumpbin`. The SDK and build tools are not installed into the package. The Windows runtime and optional graphics ICD remain system prerequisites. A smoke test on the build machine does not replace execution on a clean Windows 11 system. Debug PDBs remain in `build/obj/debug`; the optimized Release currently does not produce a separate symbol ZIP.

## Candidate release publication

The Windows job verifies the extracted ZIP and manifests before uploading its artifact. An explicitly marked release-preparation commit on the candidate branch can attach that same run's verified outputs to a **new draft** release. It refuses an existing release or tag and checks that the package was built from the exact clean commit. This does not publish or accept the candidate: the draft and hardware evidence must be reviewed before publishing. Preserve the package/version and historical evidence if another candidate is required.

### Bilingual desktop packages (0.3.0+)

Inter and JetBrains Mono are pinned to the upstream byte digests in `deps.lock`. The staged `assets/fonts/` directory is resolved from the executable path, not the caller’s current directory. The package includes both OFL notices under `LICENSES/`. The ZIP writer explicitly names entries with `/` and both writer and verifier reject `\` in a 0.3.0+ archive. The extracted smoke checks `--version` against `VERSION` and the actual Git commit, then renders in both languages and themes from a directory with spaces. The localization catalog is compiled into the executable; there is no external translation file to configure.
